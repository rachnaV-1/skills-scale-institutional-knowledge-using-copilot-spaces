# OctoAcme — Project Management Processes

This folder contains the core program process documents used by OctoAcme to run cross-functional projects. The docs are intentionally lightweight, actionable, and intended to be the single source of truth for project teams.

Overview
- Purpose: centralize project planning, execution, risk management, and continuous improvement.
- Audience: Project Managers, Product Managers, Developers, QA, and Stakeholders.
- How to use: keep these docs updated in the project repo; link to them from project READMEs and one-pagers.

Primary process documents (in this folder)
- octoacme-project-initiation.md — Steps to validate and authorize new initiatives (one-pager, stakeholders, decision gate).
- octoacme-project-planning.md — Turn approved initiatives into actionable plans and backlogs (kickoff, backlog templates, DoD).
- octoacme-execution-and-tracking.md — Day-to-day execution guidance, team rhythm, workflows, and tracking (project board, PR conventions).
- octoacme-release-and-deployment.md — Release types, pre-release checks, deployment checklist, and rollback playbook.
- octoacme-risks-and-communication.md — Risk register guidance, communication templates, and escalation paths.
- octoacme-retrospective-and-continuous-improvement.md — How to run retrospectives and convert learnings into action items.
- octoacme-roles-and-personas.md — Role summaries and responsibilities used across the process docs.

Quick start
1. For a new idea, complete the Project One-pager (see initiation doc) and get Product Lead review.
2. If approved, create a project board and populate the backlog using the Backlog Item Template (planning doc).
3. Follow the execution doc for standups, PR workflow, CI requirements, and reporting.
4. Use the release doc for deployment and post-release verifications.
5. Run retrospectives and add action items to the backlog so improvements are tracked and delivered.

Contributing process
- To propose changes to these process docs, open an issue using the included template (.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml).
- Use that issue to capture the summary, rationale, and suggested content. After review, changes should be proposed via small PRs that reference the issue.

Contact / Owners
- Project Process Maintainers: Project Manager & Product Lead (document ownership is maintained in repo README or project charter).
